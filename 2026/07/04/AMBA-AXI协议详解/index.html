第1章 AXI协议概述

1.1 什么是AXI？

AXI（Advanced eXtensible Interface，高级可扩展接口）是ARM公司AMBA总线体系结构中的一种高性能、高带宽、低延迟的系统总线协议，主要用于连接高速、高带宽的模块（如CPU、DDR控制器、GPU、DMA、高速网络接口等）。

1.2 AXI的三个主要变体

在实际SoC/FPGA设计中，AXI协议根据应用场景分为三种变体：

变体 全称 特点 典型应用场景
AXI4-FULL AXI4 for Memory-Mapped 支持突发传输（Burst），最大256拍；5个独立通道；支持Outstanding和乱序 CPU访问DDR、DMA搬运大块数据、高性能外设
AXI4-Lite AXI4-Lite for Simple Memory-Mapped 不支持突发传输（固定单拍）；5个通道简化版；寄存器接口友好 配置寄存器读写、状态查询、低吞吐率控制接口
AXI4-Stream AXI4-Stream for High-Speed Streaming 无地址通道；纯粹的流式数据传输；突发长度无限制 视频流、音频流、高速ADC/DAC数据采集、FIFO接口

关键理解：AXI4-FULL和AXI4-Lite都属于存储器映射（Memory-Mapped） 协议——每次传输都包含目标地址。而AXI4-Stream是非存储器映射的，只传输数据流，不包含地址信息，因此吞吐率更高、协议开销更小。

1.3 AXI数据位宽与地址位宽

AXI的数据总线宽度和地址总线宽度是可配置的，不同变体有不同限制：

变体 数据位宽 地址位宽 说明
AXI4-FULL 32/64/128/256 bits 32 bits（可扩展） 高性能存储器映射，支持多种位宽以适应不同带宽需求
AXI4-Lite 固定32 bits 32 bits 轻量级控制接口，简化设计
AXI4-Stream 8/16/32/64/128/… bits 无地址 流数据通道，位宽可灵活配置

在ZYNQ-7000平台中，AXI_HP接口通常采用64位或128位数据总线，而AXI_GP接口则为32位。配置完HP端口后，ZYNQ会多出一个AXI Slave端口（名称为S_AXI_HP0），但这些端口默认是AXI3标准的。如需使用AXI4协议，需要添加AXI Interconnect或AXI SmartConnect IP进行协议转换（AXI3 ↔ AXI4）。

第2章 AXI4核心架构（5通道独立）

2.1 五个独立通道概览

AXI4最核心的设计思想是将地址/控制信号与数据信号分离到不同的通道，每个通道独立握手，互不阻塞。

通道 信号前缀 传输方向（数据/地址流向） 控制方（VALID由谁发） 控制方（READY由谁发） 关键描述
读地址 AR Master → Slave（主机发出地址） Master Slave 主机告诉从机：我要读哪块地址
读数据 R Slave → Master（从机返回数据） Slave Master 从机把读到的数据和响应送回主机
写地址 AW Master → Slave（主机发出地址） Master Slave 主机告诉从机：我要往哪块地址写
写数据 W Master → Slave（主机发出数据） Master Slave 主机把要写入的实际数据发给从机
写响应 B Slave → Master（从机返回响应） Slave Master 从机告诉主机：刚才的写操作成功/失败

通道分离的目的：流水线化——地址可以在前一笔数据未完成时提前发出，实现Outstanding传输。

第3章 AXI4握手时序详解

3.1 VALID/READY双向握手机制

AXI的五个通道都使用相同的VALID/READY双向握手来传输地址、数据和控制信息。这种机制使得主机和从机之间传输数据时，双方都可以控制传输的速率。

协议的唯一铁律：VALID信号不可以依赖READY信号。也就是说，发送方（Source）只要把数据/地址准备好了，就必须把VALID拉高，不能等看到对方的READY为高再拉VALID（否则会引发死锁风险）。

信息源端使用VALID信号表示当前通道地址、数据和控制信息什么时候有效；
目的端使用READY信号表示什么时候可以接收信息。

3.2 三种握手方式

① VALID先变高，READY后变高

② READY先变高，VALID后变高

③ VALID和READY信号同时变高

3.3 工程实践中的常见发送策略

发送方角色 典型通道（读/写） 数据/地址来源 工程上常用的策略 原因
Master（主机） AW（写地址）、W（写数据）、AR（读地址） CPU/DMA内部逻辑，响应极快，一个周期内就能算出来 倾向于"同时拉高"或"READY先高" 主机通常频率高、逻辑简单，为了追求极致带宽，希望一拍之内完成握手，绝不多等
Slave（从机） R（读数据）、B（写响应） 外部存储器（DDR/Flash）、慢速外设、内部RAM（可能需多个周期读出） 几乎全是"VALID先拉高" 从机不知道何时能取到数据。当它终于取到数据放在总线上时，必须第一时间把VALID置1，然后等着主机（Master）腾出手来把READY拉高把数据拿走

第4章 突发传输（Burst）核心计算

4.1 三个核心参数

参数 信号名 含义 计算公式
突发大小 AxSIZE 每拍传输的字节数 字节数 = 2^SIZE
突发长度 AxLEN 数据传输次数编码 实际拍数 = LEN + 1
总字节数 - 一次突发的最大数据量 最大字节数 = 2^SIZE × (LEN + 1)

4.2 三种BURST类型详解

类型 值 地址计算 典型用途
FIXED（固定地址） 2’b00 地址不变化，每个beat访问相同地址 重复访问同一寄存器（如FIFO口）

【例题4.4：WRAP边界计算（标准版）】

CPU发起：

  • 起始地址：0x0000_0028
  • SIZE：3
  • LENGTH：3
  • BURST：WRAP

问：计算WRAP边界，并写出4拍地址序列。

解析：

  • 突发总大小 = 8 × 4 = 32字节
  • WRAP边界 = 32字节对齐
  • 下边界 = floor(0x28 / 32) × 32 = 0x20
  • 上边界 = 0x20 + 32 = 0x40
  • 地址序列：

    • 拍1：0x28 + 8 = 0x30

【例题4.5：WRAP边界计算（非对齐起始地址-非法场景）】

CPU发起：

  • 起始地址：0x0000_001A
  • SIZE：2
  • LENGTH：3
  • BURST：WRAP

问：这笔WRAP事务是否合法？如果只按数学回绕计算，地址序列是什么？

解析：

  • 突发总大小 = 4 × 4 = 16字节
  • 下边界 = floor(0x1A / 16) × 16 = 0x10
  • 上边界 = 0x10 + 16 = 0x20
  • 但WRAP burst的起始地址必须按每拍传输字节数对齐；SIZE=2表示4字节，0x1A不是4字节对齐地址
  • 因此这笔协议上非法，验证环境应检查Master不会发出这种WRAP事务
  • 如果只是练习回绕公式，可以得到数学序列：
    • 拍0：0x1A
    • 拍1：0x1A + 4 = 0x1E
    • 拍2：0x1E + 4 = 0x22（超过上边界0x20）→ 回绕到 0x10 + (0x22 - 0x20) = 0x12
    • 拍3：0x12 + 4 = 0x16

完整序列：0x1A, 0x1E, 0x12, 0x16

⚠️ 注意：WRAP回绕时，超出的偏移量要加上下边界，不是简单回到下边界！

第5章 AXI4读事务时序

5.1 读事务通道流程

读事务使用两个独立的通道：

  • 读地址通道（AR） ：Master发送读地址和控制信息
  • 读数据通道（R） ：Slave返回读数据和响应

5.2 读事务波形图

时序解读：

  • T0→T3：Master拉高ARVALID，Slave在T2周期拉高ARREADY，地址握手在T3上升沿完成。
  • T3→T6：Slave准备数据，在T4周期拉高RVALID，Master在T6周期拉高RREADY，数据握手在T7上升沿完成（首次数据）。
  • 地址通道和数据通道完全独立：地址握手在T3完成，数据握手在T7完成，中间有4拍延迟（这是Slave的读延迟）。
  • 突发传输：RLAST在最后一拍数据时拉高（图中A3是最后一拍）。

第6章 AXI4写事务时序

6.1 写事务通道流程

写事务使用三个独立的通道：

  • 写地址通道（AW） ：Master发送写地址和控制信息
  • 写数据通道（W） ：Master发送写数据
  • 写响应通道（B） ：Slave返回写响应

6.2 写事务波形图

时序解读：

  1. AW和W完全独立：Master在T1发地址，在T3才发数据。Slave在T3接收地址，在T5接收数据。
  2. WLAST：在最后一拍数据时拉高。
  3. B通道：Slave在收到所有数据并写入完成后才拉高BVALID返回响应。BVALID在T13或更晚出现。

第7章 数据通道与字节选通（WSTRB）

7.1 车道映射与WSTRB计算

车道（Lane）与位宽的关系：

总线位宽 车道数 地址低位决定偏移
32-bit 4 ADDR[1:0]
64-bit 8 ADDR[2:0]
128-bit 16 ADDR[3:0]
256-bit 32 ADDR[4:0]

WSTRB计算规则：

  1. 数据总线的每8bit对应1个byte lane，WSTRB[n]控制WDATA[(8n+7):8n]
  2. 起始车道通常由地址低位决定：例如128-bit总线有16个byte lane，使用ADDR[3:0]定位起始lane
  3. 对齐且完整的窄传输中，有效车道数通常为2^SIZE
  4. 对非对齐写传输，首拍可能只使能从起始地址到本数据拍边界之间的部分byte lane；不要简单地让WSTRB在同一拍内"回绕"
  5. 关键：WSTRB的bit0对应数据总线的byte 0（最低字节），低地址数据放在低编号byte lane

小端序数据分配：

  • 数据的最低字节（Byte 0）放在最低地址
  • 例如数据0xDEADBEEF，Byte 0 = 0xEF, Byte 1 = 0xBE, Byte 2 = 0xAD, Byte 3 = 0xDE

7.2 WSTRB计算完整例题

【例题7.1：32-bit总线WSTRB计算】

Master（32-bit）写数据：

  • 起始地址：0x1000_0003
  • SIZE：1

问：传输2字节，占用哪些车道？WSTRB是多少（4位二进制）？

解析：

  • 32-bit总线有4个车道（Lane 0~3）
  • 地址低2位 = 0x3 = 3（二进制11）
  • 从Lane 3开始，SIZE=1期望最多覆盖2字节，但同一拍不能把WSTRB从Lane 3回绕到Lane 0
  • 因此首拍只能使能Lane 3，WSTRB = 4’b1000
  • 后续地址推进由burst地址规则决定：非对齐INCR burst通常只有首拍非对齐，后续拍按transfer size对齐推进

⚠️ 重要结论：AXI允许非对齐INCR传输，但WSTRB不能在一个数据拍内跨总线lane边界回绕；4KB边界规则仍然必须满足。

【例题7.2：64-bit总线WSTRB计算（基础）】

GMAC（64-bit）写数据：

  • 起始地址：0x0000_000A
  • SIZE：2

问：占用哪些车道？WSTRB是多少（8位二进制）？

解析：

  • 64-bit有8个车道（Lane 0~7）
  • 地址低3位 = 0xA & 0x7 = 0x2 = 2（二进制010）
  • 从Lane 2开始，连续4个车道：Lane 2, 3, 4, 5
  • WSTRB（8位，bit0对应Lane 0）：
    • Lane 0~1：0
    • Lane 2~5：1
    • Lane 6~7：0
    • 二进制（bit7到bit0）：00111100 = 0x3C

【例题7.3：128-bit总线WSTRB计算（非对齐）】

CPU（128-bit）写DDR：

  • 起始地址：0x8000_0005
  • SIZE：2

问：占用哪些车道？WSTRB是多少（16位十六进制）？

解析：

  • 128-bit有16个车道（Lane 0~15）
  • 地址低4位 = 0x5
  • 从Lane 5开始，连续4个车道：Lane 5, 6, 7, 8
  • WSTRB（16位，bit0→Lane 0，bit15→Lane 15）：

第8章 AXI4高级特性

8.1 超前传输（Outstanding）

Outstanding是指Master在等待第一个事务的响应（R或B）之前，就可以继续发送后续事务的地址。

时序解读：

  • Master在T1、T4发送2个地址，不需要等待读数据返回。
  • Slave可以在后续连续返回数据（顺序或乱序，由ID控制）。
  • Outstanding深度 = 2（本例中）。

8.2 Outstanding深度控制

Outstanding是AXI实现高带宽的核心特性之一。它打破了传统总线"发起请求→等待响应→再发起请求"的串行模式，允许Master在未收到前一个事务响应时，就连续发出多个新事务的地址。这样，即使访问DDR这类高延迟外设，总线也能在等待期间处理其他请求，从而隐藏访问延迟，大幅提升带宽利用率。

要正确实现Outstanding，关键在于深度控制，这涉及三个层面的协同配合：

Master的发送能力（MAX_OUTSTANDING）

Master内部维护一个计数器，记录当前"在途"（已发地址但未收响应）的事务数量。这个计数器会随着地址握手成功而增加，随着响应完成而减少。

MAX_OUTSTANDING的上限通常取决于Master内部为保存在途事务信息而配备的缓冲区大小，每个在途事务需要缓存地址、控制信息以及后续返回的数据。

Interconnect的转发能力（ISSUE_CAPACITY）

总线互联结构（Interconnect）本身也有处理能力上限，需要能够容纳和转发来自多个Master的Outstanding请求。如果多个Master同时发送大量Outstanding请求，Interconnect内部的缓冲队列可能溢出。

8.3 乱序传输（Out-of-Order）与交织传输（Interleaving）

乱序传输（Out-of-Order）

  • 作用对象：不同ID（或者不同通道）的整个突发传输（Burst）。
  • 定义：主机（Manager）发出的多个写/读请求（地址通道AR/AW）的顺序，与数据通道（W/R）上完成传输的顺序，或者响应通道（B）上返回的顺序不一致。
  • 本质：请求顺序的重排。目的是让先发起但被阻塞的慢操作，让位给后发起但准备就绪的快操作。

交织传输（Interleaving）

  • 作用对象：同一个ID的单个突发传输内部的各个数据节拍（Beats）。
  • 定义：在读取回传数据（R通道）时，来自不同ID的多个突发传输的数据节拍，可以交错地在总线上进行传输。
  • 本质：数据包的分割与穿插。目的是防止某个长突发长时间占据总线，导致其他ID的短突发饿死。
比较维度 乱序传输（Out-of-Order） 交织传输（Interleaving）
粒度 Burst级别（整个突发完成顺序变化） Beat级别（突发内部单个数据传输顺序变化）
依赖标识 ARID / AWID（事务ID） RID（读数据ID，必须与ARID匹配）
响应通道（B） 允许乱序（BID顺序与AWID不同） 不涉及（写响应没有交织概念）
关键前提 从机必须声明支持OutOfOrder能力 从机必须声明支持Interleaving能力
限制规则 相同ID的突发必须严格保序 相同ID的Beat必须连续传输（中间不能插入其他ID的Beat）

核心铁律：不同ID的事务可以乱序完成，但同一ID的事务必须严格保序完成。这条铁律同时适用于读（R通道）和写（B通道），是AXI乱序机制的最高准则。通常支持交织就自然支持乱序，复杂的高性能从设备常常会同时具备这两个特性。

写数据乱序（AXI4 vs AXI3）

这是AXI4与AXI3的重大区别，也是乱序传输中最容易被误解的地方。AXI4中写通道的乱序行为需要分两个层面来看：

通道 是否允许乱序 原因
写数据（W通道） 不允许 AXI4移除了WID信号，从机只能按物理接收顺序匹配数据与地址
写响应（B通道） 允许 响应自带BID标签，从机可独立返回任何ID的完成状态

容易混淆点：“写通道乱序"≠"写数据乱序”。写数据必须顺序发送，但写响应可以乱序返回。

【例题9.1：数据宽度拆分（128-bit→32-bit）】

系统拓扑：

  • DMA：128-bit Master，发起写事务
  • SMC：32-bit Slave，地址范围0x1000_0000~0x1000_0FFF

DMA事务参数：

  • 起始地址：0x1000_0000
  • SIZE：4
  • LENGTH：3

问：Interconnect需要拆成多少笔子事务？每笔的SIZE和LENGTH如何设定？

解析：

  • 总字节 = 2^4 × (3+1) = 16 × 4 = 64字节
  • SMC最大SIZE = 2（2^2=4字节）
  • 每笔子事务最大能力：SIZE=2，LENGTH=0（单拍4字节）
  • 总子事务数 = 64 / 4 = 16笔
  • 每笔参数：SIZE=2, LENGTH=0
  • 地址序列：0x1000_0000, 0x1000_0004, 0x1000_0008, …, 0x1000_003C

【例题9.2：AXI转APB（突发拆单拍）】

系统拓扑：

  • CPU：128-bit AXI4 Master
  • APB Bridge：32-bit APB3 Slave，地址范围0x2000_0000~0x2000_00FF

CPU事务参数：

  • 起始地址：0x2000_0010
  • SIZE：2
  • LENGTH：3

问：APB不支持burst，需要拆成多少次单拍传输？写出每次的地址。

解析：

  • SIZE=2 → 每拍4字节，正好是APB的单拍能力
  • LENGTH=3 → 共4拍
  • APB无LEN字段，必须拆成4次独立的APB写操作
  • 地址序列：
    • 操作0：0x2000_0010
    • 操作1：0x2000_0014
    • 操作2：0x2000_0018
    • 操作3：0x2000_001C
  • 验证要点：检查AXI的B通道响应是否映射了APB的传输完成/错误状态

【例题9.3：数据宽度拼接（128-bit→256-bit）】

系统拓扑：

  • DMA：128-bit AXI3 Master
  • DDR：256-bit AXI4 Slave，地址范围0x8000_0000~0x8FFF_FFFF

DMA事务参数：

  • 起始地址：0x8000_0100
  • SIZE：4
  • LENGTH：1

问：DDR是256-bit总线，Interconnect如何将2拍128-bit数据拼接成1拍256-bit？

解析：

  • 2拍128-bit数据 = 32字节 = 1拍256-bit
  • 起始地址0x8000_0100，低5位=0（256-bit对齐）
  • 拼接方式：
    • 拍0的数据放到256-bit总线的低128位（byte 0~15）
    • 拍1的数据放到256-bit总线的高128位（byte 16~31）
  • 合并后的WSTRB = 32位全1（如果DMA的WSTRB全有效）
  • 验证要点：检查拼接顺序是否正确（低地址对应低字节）

【例题9.4：跨协议+跨宽度混合转换】

系统拓扑：

  • CPU：128-bit AXI4 Master
  • APB Bridge：32-bit APB3 Slave

CPU事务参数：

  • 起始地址：0x2000_0002（非对齐！）
  • SIZE：3
  • LENGTH：1

问：Interconnect需要如何处理这笔事务？

解析：

  • 第一步：识别AXI侧事务
    • SIZE=3 → 每拍最多8字节
    • LENGTH=1 → 2拍
    • 起始地址0x2000_0002非8字节对齐，因此首拍是非对齐写
  • 第二步：生成AXI侧可观察行为
    • 首拍从地址0x2000_0002开始，128-bit总线下可使用Lane 2~9，WSTRB=0x03FC
    • Aligned_Address = floor(0x2000_0002 / 8) × 8 = 0x2000_0000
    • 第二拍地址 = 0x2000_0000 + 8 = 0x2000_0008，可使用Lane 8~15，WSTRB=0xFF00
  • 第三步：转换到APB
    • APB3本身没有PSTRB，常见APB4才有PSTRB；如果下游是APB3，Bridge通常需要读改写或拆成更小粒度访问来保护未选中字节
    • 如果Bridge面向32-bit APB4并支持PSTRB，可拆成若干32-bit单拍访问，例如覆盖0x2000_0000、0x2000_0004、0x2000_0008、0x2000_000C等对齐字地址，并按PSTRB屏蔽无效字节
  • 验证要点：检查WSTRB在每一步转换中的正确性

10.2 完整例题

【例题10.1：AXI3最大长度检查】

DMA是AXI3 Master，发起事务：

  • SIZE：4
  • LENGTH：0xF

问：这笔事务是否合法？总共传输多少字节？

解析：

  • LENGTH=15 → 实际拍数 = 15+1 = 16拍
  • AXI3最大LEN=15 → 合法（正好达到上限）
  • 总字节 = 16 × 16 = 256字节

【例题10.2：AXI3超长突发处理】

接上题，如果DMA想传输512字节（32拍），应如何拆分？

解析：

  • AXI3单笔最大16拍，512字节/16字节/拍 = 32拍
  • 最少拆成2笔：
    • 子事务1：SIZE=4, LENGTH=0xF（16拍，256字节）
    • 子事务2：SIZE=4, LENGTH=0xF（16拍，256字节）
  • 地址：
    • 子事务1：起始0x8000_0100
    • 子事务2：起始0x8000_0200
  • 验证要点：检查发起端、DMA描述符生成逻辑或协议Bridge是否按AXI3限制拆分，且拆分后的地址连续

【例题10.3：WSTRB与地址对齐检查】

AXI Slave收到一笔写事务：

  • SIZE：2
  • WSTRB = 0xF0

问：这笔事务是否合法？为什么？

解析：

  • SIZE=2 → 4字节传输，应该有4个bit为1

  • WSTRB=0xF0 → bit4~7为1，共4个bit

  • 看起来数量对，但位置不对！

  • 对于4字节传输，有效bit应该是连续的4个bit，且与地址低位对齐

  • 如果地址低3位=0，WSTRB应为0x0F（bit0~3）

  • 如果WSTRB=0xF0（bit4~7），说明传输的4字节从byte4开始

  • 这要求地址低3位=4，且总线至少8字节宽

  • 需要具体分析：如果地址低3位=4，则合法；否则非法

  • 更典型的检查：如果SIZE=2且地址低3位=0，WSTRB应落在bit0~bit3范围内；如果地址低3位=4，WSTRB=0xF0才匹配

【例题10.4：非法LEN与桥接场景区分】

系统中有AXI3 Master连接到AXI4 Interconnect，Master发出：

  • 起始地址：0x0000_0000
  • SIZE：3
  • LENGTH：0x1F

问：Interconnect应如何处理？

解析：

  • AXI3不支持LEN=31（超过15）
  • 如果这确实是一个AXI3 Master直接发出的事务，Master本身已经违反协议，Slave/Interconnect通常只能报错或拒绝，不能把非法输入当成合规场景
  • 如果真实场景是"AXI4 Master通过Bridge访问AXI3 Slave"，Bridge才应该在AXI3侧拆成合法子事务：
    • 子事务1：LENGTH=0xF（16拍）
    • 子事务2：LENGTH=0xF（16拍）
  • 验证要点：区分"上游非法事务检查"和"合法协议转换拆分"，不要把AXI3 Master发出LEN=0x1F当成正常激励

第14章 AXI4-Stream协议详解

14.1 AXI4-Stream概述

AXI4-Stream与AXI4-FULL最大的区别是：没有地址通道。它不涉及"读某个地址"或"写某个地址"，只有纯粹的数据流发送与接收。这使得它非常适合视频流、音频流、高速ADC/DAC数据采集等场景。

关键规则：

【综合题A：完整系统事务分析】

系统拓扑：

  • Master A：128-bit AXI4
  • Master B：64-bit AXI3
  • Slave X：32-bit AXI3（地址0x0000_0000~0x0000_FFFF）
  • Slave Y：256-bit AXI4（地址0x8000_0000~0x8FFF_FFFF）
  • APB Bridge：32-bit APB3（地址0x2000_0000~0x2000_00FF）

事务1：Master A写Slave X

  • 地址：0x0000_000A
  • SIZE：3
  • LENGTH：2
  • BURST：INCR
  • 数据：0xAABBCCDD_EEFF0011

问：

  1. 每拍地址是多少？
  2. 每拍的WSTRB是多少（128-bit总线）？
  3. 需要拆成多少笔子事务给Slave X（32-bit）？
  4. 拆分后每笔的地址和WSTRB？

解析：

  • 1. 每拍地址：

    • 拍0：0x0000_000A
    • Number_Bytes = 2^3 = 8，Aligned_Address = floor(0x0000_000A / 8) × 8 = 0x0000_0008
    • INCR burst只有首拍可以从非对齐地址开始，后续拍按传输大小对齐推进
    • 拍1：0x0000_0008 + 8 = 0x0000_0010
    • 拍2：0x0000_0008 + 16 = 0x0000_0018

  • 2. 每拍WSTRB（128-bit=16车道）：

    • 拍0（0x0A，低4位=10）：
      • 首拍从Lane 10开始，到当前128-bit数据拍末尾Lane 15结束
      • WSTRB = 0xFC00（二进制 1111 1100 0000 0000）
    • 拍1（0x10，低4位=0）：
      • 从Lane 0开始连续8个车道：Lane 0~7
      • WSTRB = 0x00FF（二进制 0000 0000 1111 1111）
    • 拍2（0x18，低4位=8）：
      • 从Lane 8开始连续8个车道：Lane 8~15
      • WSTRB = 0xFF00（二进制 1111 1111 0000 0000）

  • 3. 拆给Slave X（32-bit）：

    • AXI侧3拍最多承载24字节，但首拍非对齐，按上述WSTRB实际覆盖地址0x0000_000A~0x0000_001F，共22个有效字节
    • Slave X每拍4字节，32-bit对齐字地址覆盖：0x0000_0008、0x0000_000C、0x0000_0010、0x0000_0014、0x0000_0018、0x0000_001C
    • 因此需要拆成6笔32-bit单拍写，首笔WSTRB=4’b1100，其余5笔WSTRB=4’b1111

  • 4. 拆分后每笔地址和WSTRB：

    子事务 地址 32-bit WSTRB 覆盖字节
    0 0x0000_0008 4’b1100 0x0000_000A~0x0000_000B
    1 0x0000_000C 4’b1111 0x0000_000C~0x0000_000F
    2 0x0000_0010 4’b1111 0x0000_0010~0x0000_0013
    3 0x0000_0014 4’b1111 0x0000_0014~0x0000_0017
    4 0x0000_0018 4’b1111 0x0000_0018~0x0000_001B
    5 0x0000_001C 4’b1111 0x0000_001C~0x0000_001F
