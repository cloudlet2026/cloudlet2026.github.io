第1章 AXI协议概述

1.1 什么是AXI？

AXI（Advanced eXtensible Interface，高级可扩展接口）是ARM公司AMBA总线体系结构中的一种高性能、高带宽、低延迟的系统总线协议，主要用于连接高速、高带宽的模块（如CPU、DDR控制器、GPU、DMA、高速网络接口等）。

1.2 AXI的三个主要变体

在实际SoC/FPGA设计中，AXI协议根据应用场景分为三种变体：

变体 全称 特点 典型应用场景
AXI4-FULL AXI4 for Memory-Mapped 支持突发传输（Burst），最大256拍；5个独立通道；支持Outstanding和乱序 CPU访问DDR、DMA搬运大块数据、高性能外设
AXI4-Lite AXI4-Lite for Simple Memory-Mapped 不支持突发传输（固定单拍）；5个通道简化版；寄存器接口友好 配置寄存器读写、状态查询、低吞吐率控制接口
AXI4-Stream AXI4-Stream for High-Speed Streaming 无地址通道；纯粹的流式数据传输；突发长度无限制 视频流、音频流、高速ADC/DAC数据采集、FIFO接口

关键理解：AXI4-FULL和AXI4-Lite都属于存储器映射（Memory-Mapped） 协议——每次传输都包含目标地址。而AXI4-Stream是非存储器映射的，只传输数据流，不包含地址信息，因此吞吐率更高、协议开销更小。

1.3 AXI数据位宽与地址位宽

AXI的数据总线宽度和地址总线宽度是可配置的，不同变体有不同限制：

变体 数据位宽 地址位宽 说明
AXI4-FULL 32/64/128/256 bits 32 bits（可扩展） 高性能存储器映射，支持多种位宽以适应不同带宽需求
AXI4-Lite 固定32 bits 32 bits 轻量级控制接口，简化设计
AXI4-Stream 8/16/32/64/128/… bits 无地址 流数据通道，位宽可灵活配置

在ZYNQ-7000平台中，AXI_HP接口通常采用64位或128位数据总线，而AXI_GP接口则为32位。配置完HP端口后，ZYNQ会多出一个AXI Slave端口（名称为S_AXI_HP0），但这些端口默认是AXI3标准的。如需使用AXI4协议，需要添加AXI Interconnect或AXI SmartConnect IP进行协议转换（AXI3 ↔ AXI4）。

2.1 五个独立通道概览

AXI4最核心的设计思想是将地址/控制信号与数据信号分离到不同的通道，每个通道独立握手，互不阻塞。

第3章 AXI4握手时序详解

3.1 VALID/READY双向握手机制

AXI的五个通道都使用相同的VALID/READY双向握手来传输地址、数据和控制信息。这种机制使得主机和从机之间传输数据时，双方都可以控制传输的速率。

协议的唯一铁律：VALID信号不可以依赖READY信号。也就是说，发送方（Source）只要把数据/地址准备好了，就必须把VALID拉高，不能等看到对方的READY为高再拉VALID（否则会引发死锁风险）。

信息源端使用VALID信号表示当前通道地址、数据和控制信息什么时候有效；
目的端使用READY信号表示什么时候可以接收信息。

3.2 三种握手方式

① VALID先变高，READY后变高

② READY先变高，VALID后变高

③ VALID和READY信号同时变高

3.3 工程实践中的常见发送策略

发送方角色 典型通道（读/写） 数据/地址来源 工程上常用的策略 原因
Master（主机） AW（写地址）、W（写数据）、AR（读地址） CPU/DMA内部逻辑，响应极快，一个周期内就能算出来 倾向于"同时拉高"或"READY先高" 主机通常频率高、逻辑简单，为了追求极致带宽，希望一拍之内完成握手，绝不多等
Slave（从机） R（读数据）、B（写响应） 外部存储器（DDR/Flash）、慢速外设、内部RAM（可能需多个周期读出） 几乎全是"VALID先拉高" 从机不知道何时能取到数据。当它终于取到数据放在总线上时，必须第一时间把VALID置1，然后等着主机（Master）腾出手来把READY拉高把数据拿走

第4章 AXI4读事务时序

4.1 读事务通道流程

读事务使用两个独立的通道：

  • 读地址通道（AR） ：Master发送读地址和控制信息
  • 读数据通道（R） ：Slave返回读数据和响应

4.2 读事务波形图

时序解读：

  • T0→T3：Master拉高ARVALID，Slave在T2周期拉高ARREADY，地址握手在T3上升沿完成。
  • T3→T6：Slave准备数据，在T4周期拉高RVALID，Master在T6周期拉高RREADY，数据握手在T7上升沿完成（首次数据）。
  • 地址通道和数据通道完全独立：地址握手在T3完成，数据握手在T7完成，中间有4拍延迟（这是Slave的读延迟）。
  • 突发传输：RLAST在最后一拍数据时拉高（图中A3是最后一拍）。

第5章 AXI4写事务时序

5.1 写事务通道流程

写事务使用三个独立的通道：

  • 写地址通道（AW） ：Master发送写地址和控制信息
  • 写数据通道（W） ：Master发送写数据
  • 写响应通道（B） ：Slave返回写响应

5.2 写事务波形图

时序解读：

  1. AW和W完全独立：Master在T1发地址，在T3才发数据。Slave在T3接收地址，在T5接收数据。
  2. WLAST：在最后一拍数据时拉高。
  3. B通道：Slave在收到所有数据并写入完成后才拉高BVALID返回响应。BVALID在T13或更晚出现。

第6章 突发传输详解

6.1 突发传输的基本概念

突发传输（Burst Transfer）是AXI4-FULL的核心特性之一，允许在一次事务中连续传输多个数据。

参数 信号名 含义 取值范围
突发长度 AxLEN 数据传输的次数 0~255（实际长度为AxLEN+1），AXI4-Lite固定为0
突发大小 AxSIZE 每拍传输的数据字节数 0~7（实际大小为2^AxSIZE字节）
突发类型 AxBURST 地址计算方式 00=FIXED, 01=INCR, 10=WRAP

6.2 突发类型详解

1. FIXED（固定地址）

地址不变化，每个beat访问相同地址。

  • 典型用途：重复访问同一寄存器（如FIFO口）。
  • 示例：起始地址0x100，Burst Length=4，地址序列为0x100, 0x100, 0x100, 0x100。

2. INCR（递增地址）——最常用

地址按beat递增，递增量为传输数据宽度（字节数）。

  • 典型用途：线性缓冲区、内存拷贝、DMA搬运。
  • 示例：32位总线，起始地址0x100，Burst Length=4，地址序列为0x100, 0x104, 0x108, 0x10C。
  • 特殊规则：INCR突发可以跨越1KB边界，但协议限制不能跨越4KB地址边界（这是AXI的地址空间保护边界）。若突发会跨4KB，则必须拆分。

3. WRAP（回环突发）

主要用于缓存行填充（Cache Line Fill）。地址递增，但当到达回环边界时，地址跳回起始地址对齐的边界。

  • 回环边界 = 突发总大小（Burst Size × Burst Length），并且必须是2的幂。
  • 典型用途：Cache Line操作（如ARM的LDP/STP指令）。

6.3 地址对齐

每个数据传输单元的大小会与传输单元的边界对齐。例如，32位宽的数据传输通常以4字节为单位进行对齐。但在某些应用场景中，可能需要从非对齐地址开始数据传输突发。

对齐指的是突发传输中起始地址与数据总线宽度之间的关系。图中每行对应一次传输操作，根据地址与控制信息判断，阴影区域表示未传输的字节。

当起始地址 % 数据总线宽度（字节数） == 0时，地址是对齐的。

当地址非对齐时，第一次传输中，数据会被移位到对应的字节通道上。由从机（Slave）或互连逻辑负责处理未对齐地址，通过WSTRB或读取后的移位来实现。

例如下面这个示例中，第一次传输的WSTRB = 4'b1110，屏蔽0x00地址上的数据，其余传输的WSTRB = 4'b1111。

第一次传输的WSTRB = 4'b1000，屏蔽0x04、0x05、0x06地址上的数据，其余传输的WSTRB = 4'b1111。

第7章 AXI4高级特性

7.1 超前传输（Outstanding）

Outstanding是指Master在等待第一个事务的响应（R或B）之前，就可以继续发送后续事务的地址。

时序解读：

  • Master在T1、T4发送2个地址，不需要等待读数据返回。
  • Slave可以在后续连续返回数据（顺序或乱序，由ID控制）。
  • Outstanding深度 = 2（本例中）。

7.2 乱序传输（Out-of-Order）与交织传输（Interleaving）

乱序传输（Out-of-Order）

  • 作用对象：不同ID（或者不同通道）的整个突发传输（Burst）。
  • 定义：主机（Manager）发出的多个写/读请求（地址通道AR/AW）的顺序，与数据通道（W/R）上完成传输的顺序，或者响应通道（B）上返回的顺序不一致。
  • 本质：请求顺序的重排。目的是让先发起但被阻塞的慢操作，让位给后发起但准备就绪的快操作。

交织传输（Interleaving）

  • 作用对象：同一个ID的单个突发传输内部的各个数据节拍（Beats）。
  • 定义：在读取回传数据（R通道）时，来自不同ID的多个突发传输的数据节拍，可以交错地在总线上进行传输。
  • 本质：数据包的分割与穿插。目的是防止某个长突发长时间占据总线，导致其他ID的短突发饿死。
比较维度 乱序传输（Out-of-Order） 交织传输（Interleaving）
粒度 Burst级别（整个突发完成顺序变化） Beat级别（突发内部单个数据传输顺序变化）
依赖标识 ARID / AWID（事务ID） RID（读数据ID，必须与ARID匹配）
响应通道（B） 允许乱序（BID顺序与AWID不同） 不涉及（写响应没有交织概念）
关键前提 从机必须声明支持OutOfOrder能力 从机必须声明支持Interleaving能力
限制规则 相同ID的突发必须严格保序 相同ID的Beat必须连续传输（中间不能插入其他ID的Beat）

核心铁律：不同ID的事务可以乱序完成，但同一ID的事务必须严格保序完成。这条铁律同时适用于读（R通道）和写（B通道），是AXI乱序机制的最高准则。通常支持交织就自然支持乱序，复杂的高性能从设备常常会同时具备这两个特性。

写数据乱序（AXI4 vs AXI3）

这是AXI4与AXI3的重大区别，也是乱序传输中最容易被误解的地方。AXI4中写通道的乱序行为需要分两个层面来看：

通道 是否允许乱序 原因
写数据（W通道） 不允许 AXI4移除了WID信号，从机只能按物理接收顺序匹配数据与地址
写响应（B通道） 允许 响应自带BID标签，从机可独立返回任何ID的完成状态

容易混淆点：“写通道乱序"≠"写数据乱序”。写数据必须顺序发送，但写响应可以乱序返回。

工程实践注：在实际SoC设计中，交织虽然能提高吞吐，但会极大增加从机内部的状态机复杂度（需要维护多个RID的当前计数值）。因此，AXI4协议规定，交织深度（Interleaving Depth）必须由从机在RUSER或配置参数中声明，且主机在发起传输时，需要确保接收缓冲区能够容纳交织带来的乱序数据重组压力。

7.3 AXI4的Outstanding深度控制

Outstanding是AXI实现高带宽的核心特性之一。它打破了传统总线"发起请求→等待响应→再发起请求"的串行模式，允许Master在未收到前一个事务响应时，就连续发出多个新事务的地址。这样，即使访问DDR这类高延迟外设，总线也能在等待期间处理其他请求，从而隐藏访问延迟，大幅提升带宽利用率。

要正确实现Outstanding，关键在于深度控制，这涉及三个层面的协同配合：

Master的发送能力（MAX_OUTSTANDING）

Master内部维护一个计数器，记录当前"在途"（已发地址但未收响应）的事务数量。这个计数器会随着地址握手成功而增加，随着响应完成而减少。

MAX_OUTSTANDING的上限通常取决于Master内部为保存在途事务信息而配备的缓冲区大小，每个在途事务需要缓存地址、控制信息以及后续返回的数据。

Interconnect的转发能力（ISSUE_CAPACITY）

总线互联结构（Interconnect）本身也有处理能力上限，需要能够容纳和转发来自多个Master的Outstanding请求。如果多个Master同时发送大量Outstanding请求，Interconnect内部的缓冲队列可能溢出。

Slave的接收能力（ACCEPT_CAPACITY）

Slave通常有自己的队列来缓存接收到的请求。如果Slave的Outstanding能力为N，意味着它可以同时处理N个未完成的事务。如果Master发送速度过快，超过了Slave的处理能力，Slave可以通过拉低对应的AxREADY信号来进行反压，告诉Master"我暂时处理不了新的请求了"。

第8章 AXI4-Lite Slave RTL代码

AXI4-Lite是AXI的简化版，不支持突发传输（LEN固定为0），但保留了完整的5通道握手。它最适合作为寄存器的配置接口。

AXI4-Lite Slave 代码要点：

  1. 地址和数据通道独立握手：状态机同时监测AWVALID和WVALID，支持地址先到或数据先到。
  2. 写响应延迟：必须等到地址和数据都握手完成后，才进入WR_RESP状态返回BVALID。
  3. WSTRB字节选通：支持部分字节写入，适用于对32位寄存器中个别字节的更新。
  4. 读数据零延迟：使用组合逻辑，ARVALID有效时RDATA在同一周期输出（适用于寄存器读）。

第10章 AXI4-Stream协议详解

10.1 AXI4-Stream概述

AXI4-Stream与AXI4-FULL最大的区别是：没有地址通道。它不涉及"读某个地址"或"写某个地址"，只有纯粹的数据流发送与接收。这使得它非常适合视频流、音频流、高速ADC/DAC数据采集等场景。

10.2 核心信号

信号 方向 描述
ACLK - 全局时钟，上升沿采样
ARESETn - 低电平复位，复位期间TVALID必须为0
TVALID Master→Slave 主机数据有效标志
TREADY Slave→Master 从机准备好接收
TDATA Master→Slave 数据总线（宽度可配置）
TSTRB Master→Slave 字节类型标志（1=数据字节，0=位置字节）
TKEEP Master→Slave 字节有效标志（1=该字节需传输到目的地）
TLAST Master→Slave 当前Packet的最后一个数据
TID Master→Slave 数据流标识符（可选）
TDEST Master→Slave 路由信息（可选）
TUSER Master→Slave 用户自定义信息（可选）

10.3 握手机制

AXI4-Stream的握手与AXI4一致，遵循VALID/READY双向握手机制：

关键规则：

  1. Master不能等TREADY拉高才拉TVALID。一旦TVALID拉高，必须保持直到握手完成（TVALID && TREADY）。
  2. Slave可以等TVALID拉高再拉TREADY，也可以提前拉TREADY。
  3. TLAST在Packet最后一个数据时拉高，表示本次流传输结束。

第11章 ZYNQ平台AXI互联系统架构

11.1 ZYNQ平台AXI接口分类

在Xilinx ZYNQ-7000系列FPGA中，PS（Processing System）与PL（Programmable Logic）之间通过多种AXI接口互联：

接口类型 全称 主机(Manager) 从机(Subordinate) 数据位宽 用途
AXI_GP General Purpose AXI PS PL 32位 通用控制接口，PS配置PL中的IP寄存器
AXI_HP High Performance AXI PL PS 32/64位 高性能数据传输，PL直接访问PS的DDR
AXI_ACP Accelerator Coherency Port PL PS 64位 加速器一致性端口，PL访问PS的Cache一致性域

术语说明：在最新的AXI规范中，“Master"改称为"Manager”（主机），“Slave"改称为"Subordinate”（从机）。两者含义相同，本文根据上下文交替使用。

关键理解：

  • AXI_GP：PS作为主机，PL作为从机。主要用于PS配置PL中的IP核寄存器（通过AXI-Lite），吞吐量较低。
  • AXI_HP：PL作为主机，PS作为从机。PL发送给PS的数据，经过AXI_HP接口后进入DDR3控制器，然后写入DDR3。同样，PL可通过AXI_HP接口读DDR3中的数据。这是PL与DDR之间高速数据传输的主要通道。
  • AXI_ACP：PL作为主机，PS作为从机。与HP类似，但ACP接口连接到PS的Cache一致性域，适合需要保持Cache一致性的加速器场景。

11.2 AXI Interconnect与AXI SmartConnect

在ZYNQ设计中，AXI Interconnect IP和AXI SmartConnect IP都用于连接单个/多个存储器映射主从机：

  • AXI Interconnect：传统互联IP，功能完整，但资源占用较大，延迟相对较高。
  • AXI SmartConnect：新一代互联IP，能够提供更低的延迟和更少的资源占用。Xilinx推荐优先使用SmartConnect，资源不够时再考虑Interconnect。

协议转换提示：AXI_HP端口默认是AXI3标准的，而多数PL IP使用AXI4协议。因此通常需要添加AXI Interconnect或AXI SmartConnect IP进行协议转换（AXI3 ↔ AXI4），并自动完成时钟域跨域和位宽匹配。

11.3 典型的AXI4互联系统

一个完整的AXI4系统包含：

  • AXI Interconnect/SmartConnect：地址译码 + 仲裁 + 路由
  • 多个Master（Manager） ：CPU、DMA
  • 多个Slave（Subordinate） ：DDR控制器、AXI-to-APB桥、GPIO、UART

第12章 AXI-DMA在ZYNQ平台上的应用案例

12.1 AXI-DMA概述

AXI-DMA是Xilinx提供的一个高性能DMA控制器IP，它通过AXI4-FULL接口访问内存，并通过AXI4-Stream接口与PL中的数据流处理逻辑对接。

AXI-DMA本质上是一个双向数据搬运引擎：

  • MM2S（Memory-Mapped to Stream） ：从DDR/内存读取数据，输出到AXI-Stream流
  • S2MM（Stream to Memory-Mapped） ：从AXI-Stream流接收数据，写入DDR/内存
