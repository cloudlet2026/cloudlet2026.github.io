1.1 核心组件职责与硬件边界

  • ASIB (AMBA Slave Interface Block)：挂载于各主设备的时钟域（如 aclk_m0）。主要负责接收 Master 发起的 AXI3 / AXI4 / AHB / APB 事务，执行地址译码、重映射窗口命中检测、ID 扩展以及 QoS / QVN 前端标记。
  • AMIB (AMBA Master Interface Block)：挂载于各从设备的时钟域（如 aclk_s0）。负责将 Switch 路由出的内部格式转换为目标 Slave 协议（如 AXI4 →\to→ AXI3 突发拆分、Downsizer 位宽切分、ID 还原映射），并汇总合并响应通道。
  • IB (Interface Block)：位于 ASIB/AMIB 与 Switch 之间，或 Switch 级联路径中。实现异步跨时钟域（CDC）隔离、同源异频/同频异步相位对齐以及时序收敛切断（Register Slice）。
  • Switch Matrix (Crossbar Core)：运行在独立或主干时钟域（aclk_matrix）。包含仲裁逻辑单元（Arbiter）、交叉开关数据链路、通道锁定以及 QVN 信用追踪计数器。

2. Register Slice 选型与微架构实现

AXI 握手协议遵循 VALID 与 READY 双向依赖约束。在芯片物理实现（P&R）中，长走线与复杂的扇出/仲裁逻辑会导致时序违例（Setup/Hold Violations）。NIC-400 提供三种切断时序路径的 Register Slice 单元。

3. 跨时钟域 (CDC) 与异步 FIFO 工程实现

3.1 时钟关系分类与处理策略

  • identical（同源同频）：时钟由同一 PLL 分配且无相位偏移，直连无需 IB。
  • sync（同源有理倍数关系）：如 1.2 GHz↔400 MHz1.2\text{ GHz} \leftrightarrow 400\text{ MHz}1.2 GHz↔400 MHz。可通过基于使能脉冲（Enable Pulse）的同步 FIFO 实现跨域，延迟低于纯异步架构。
  • async（完全异步或同频异源）：如独立的片上振荡器或不同 PLL 驱动。必须采用基于双口 RAM 和格雷码同步的异步 FIFO。

4. 协议转换与 AXI4 ➡ AXI3 突发拆分微架构

5.1 响应合并规则（Response Merging）

Downsizer 在拆分事务后，需收集所有子拍的 RRESP / BRESP 信号。依据 ARM AMBA 规范，合并时的优先级如下：

Priority: DECERR (2'b11) > SLVERR (2'b10) > OKAY (2'b00) / EXOKAY (2'b01)

  • 只要有任意一拍返回 DECERR，最终响应即判定为 DECERR。
  • 若无 DECERR 但存在 SLVERR，返回 SLVERR。
  • 只有所有子传输均返回 EXOKAY 时，才返回 EXOKAY；否则若无错误则返回 OKAY。

7. QoS-400 流量整形与 QVN-400 信用流控

7.1 QoS-400 调节器架构（Token Bucket / TSPEC）

QoS-400 通过 ARQOS / AWQOS 信号控制优先级。其内部基于漏桶算法（TSPEC）监测瞬时突发流量：

  • 峰值速率限制（Peak Rate, ppp）：限制单位时间内的最大事务发放量。
  • 持续速率（Average Rate, rrr）：定义长期平均带宽。
  • 突发容量（Burst Size, bbb）：桶的最大深度，允许短时间的高带宽利用。

7.2 QVN-400 虚拟网络与信用机制（Credit-Based Flow Control）

QVN-400 旨在彻底杜绝队头阻塞（Head-of-Line Blocking）。当高优先级与低优先级事务共享物理数据通道时，慢速从设备若发生反压，可能阻塞后续发往高速设备的数据。

    sequenceDiagram
    participant ASIB as ASIB (Master)
    participant AMIB as AMIB (Slave)

    Note over ASIB: QVN Credit Counter<br>[ VN0: 4 ] [ VN1: 0 ]

    ASIB ->> AMIB: ① Has VN0 Credit ➡ Issue Request
    Note over AMIB: Slave Buffer Tracker<br>Free Slots: 4
    AMIB ->> AMIB: ② Consumes buffer / Process Tx
    AMIB ->> AMIB: ③ Buffer freed
    AMIB ->> ASIB: ④ Return Token (Credit Pulse)

    Note over ASIB: VN0 Credit +1

  • 每个 Slave 接口在 AMIB 端公开其接收缓冲池可用容量（Credits）。

  • ASIB 在发起事务前核验目标 VN 是否有剩余 Credit：

  • 若 Credit > 0，允许仲裁并发射，同时 Credit ➡ Credit - 1。

  • 若 Credit == 0，在源端挂起该通道，其他指向空闲从设备的事务继续通行。

  • AMIB 释放缓冲后，通过侧带引脚向 ASIB 返还 Token 脉冲。

8. 异常处理与 E.E.W.R 机制

8.1 E.E.W.R (Early-Early Write Response) 行为时序

在 AHB 转 AXI 场景下，AHB 协议要求紧随写数据后给出响应。为消除 AXI 写响应带来的跨总线等待周期，NIC-400 提供 E.E.W.R 机制：

    sequenceDiagram
    participant AHB as AHB Bus
    participant AXI as AXI Matrix
    participant GPV as GPV Module

    Note over AHB: ADDR
    Note over AHB: DATA
    Note over AHB: ASIB Buffer
    AHB ->> AXI: Write to Matrix
    AHB ->> AHB: HRESP = OKAY (立即返回)

    Note over AXI: Write Matrix
    Note over AXI: Slave
    AXI -->> AXI: Returns SLVERR/DECERR!

    AXI ->> GPV: Error Log
    GPV ->> GPV: GPV Error Register Log
    GPV -->> GPV: Trigger Interrupt IRQ
  • 正常流程：写数据进入 ASIB 内部 FIFO 后，ASIB 立即向 AHB Master 返回 HRESP = OKAY。
  • 异常拦截与 GPV 记录：当下游 AXI 从设备实际返回 SLVERR 或 DECERR 时，由于 AHB 传输已闭合，错误信息被转存至 NIC-400 的 GPV (Global Programmer’s View) 寄存器组，同时触发系统级中断通知处理器核心。
