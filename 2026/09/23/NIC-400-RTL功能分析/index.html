NIC-400 RTL功能分析

发表于2026-09-23|更新于2026-09-23
|浏览量:

第一部分：NIC-400 主要功能详细描述

NIC-400 是 ARM 面向 AMBA 4 协议族设计的可配置互连组件（Network Interconnect），核心价值在于灵活的拓扑构建与精细的服务质量管控，支持从简单的单桥到包含最多 128 个主接口和 64 个从接口的复杂网络。

1. 多协议互连与转换

NIC-400 支持 AXI3、AXI4、AHB-Lite 及 APB 协议族。

  • AXI 主/从：完整的 AXI 全双工互连，支持独立的读写地址/数据通道。
  • AHB-Lite 主设备适配：可配置 INCR promotion and Early Write Response 选项，将 AHB 固定长度突发和 INCR 突发转换为 AXI 突发，同时提前返回写响应以提升吞吐。
  • APB 从设备接入：通过 amib_apb / ib_apb_m 实现 AXI 到 APB 的协议降级转换。
  • ITB 桥接：axi_to_itb 与 itb_address_format 实现 AXI 事务到 ITB（互连事务桥）格式的转换，支持 APB、A664 等特定协议从设备的接入。
  • 错误响应：对于不满足 GPV 安全访问规则的非法事务，default_slave_ds 返回 DECERR 错误响应。

2. 全局编程视图（GPV）

所有配置寄存器通过 GPV（Global Programmers View） 暴露给软件。

  • 寄存器被划分为多个 4KB 块，基地址由节点编号在配置时确定，无连续性要求。
  • 访问限制：仅支持 AxSIZE=32 的安全事务（AxPROT[1]=0b0），且只支持对齐访问和全 strobe 写数据。
  • 通过 ib_gpv_ib_s（从端）和 ib_gpv_ib_m（主端）实现配置访问的收发。
  • 典型寄存器包括 max_ot（最大 outstanding 事务数）、qos_range（QoS 范围）、read_qos/write_qos 等。

3. QoS-400 服务质量调节

QoS-400 是可单独授权的扩展组件，提供三类调节机制：

调节类型 机制说明
事务速率调节 基于 TSPEC 参数（峰值速率 p、突发容限 b、平均速率 r）限制主设备发出地址请求的速率。
未完成事务数调节 限制每个主设备可同时存在的未完成读/写事务数，防止从设备过载。
事务/地址延迟调节 通过反馈控制动态修改 axqos 值以瞄准目标延迟。实际延迟高于目标时提高 QoS 值以降低延迟。

📌 利用 Little's Law 关系（RT=NT×1/LTR_T = N_T \times 1/L_TRT​=NT​×1/LT​），通过背压机制防止从设备过载。

4. 数据位宽与时钟域适配

  • 位宽转换：通过 downsize（降位宽，如 64bit→32bit）和 upsize（升位宽）模块处理，配合写合并缓冲（Write Merge Buffer）处理拆分事务的响应聚合。
  • 时钟域转换：boundary_chan_slice 用于跨时钟域（CDC）处理，支持 ASYNC、SYNC 1:1、SYNC n:m 等多种同步模式。
  • 异步桥：apb_async_s / apb_async_m 处理 APB 与 AXI 时钟域之间的同步。

5. 安全与错误保护

  • TrustZone 支持：通过 AxPROT[1] 信号实现安全/非安全访问控制。
  • 安全属性检查：asib_CPU 等模块中的 spi_cdas 逻辑负责安全属性检查。
  • GPV 访问强制安全：配置寄存器访问必须为安全事务。
  • 默认从设备：default_slave_ds 拦截所有未映射地址访问并返回 DECERR。

6. 事务跟踪与乱序完成

  • Transaction Tracker（TT）：位于 switch_ml_build 中，每个 Slave 端口独立进行事务跟踪。
  • 支持乱序完成、事务 ID 匹配、响应聚合与背压流控。

7. 功耗管理

  • 支持层次化时钟门控以降低空闲功耗。

第二部分：代码结构完整功能分析

一、APB 子系统

cd_apb_c（APB 子系统控制器）

  • 定位：APB 总线互连的顶层控制器。
  • 功能：管理 APB 协议接口的配置、时钟与数据通路，是 NIC-400 中处理低速外设互连的顶层模块。
  • 代码实现逻辑：cd_apb_c 作为顶层封装，实例化 APB 互连核心与各接口块。内部通过 pclken 信号进行时钟门控，状态机仅在使能边沿工作以节省功耗。
内部子模块：

amib_apb（APB 主接口块）

  • 功能：将内部总线协议转换为 APB 协议，发起对外部 APB 设备的读写。
  • 代码实现逻辑：地址和数据通过 w_master_port_chan_slice 流水线寄存器进入，APB 状态机控制 PSEL、PENABLE、PWRITE 等信号的时序。写数据在 PWDATA 上输出，读数据在 PRDATA 上采样。
  • 子模块：
    • apb_m：APB 主端口逻辑。实现 APB 主端的状态机，控制 PSEL/PENABLE/PWRITE 的时序生成。
    • w_master_port_chan_slice：写通道切片，处理写数据/地址流水线。在写通道中插入寄存器级，切断长组合路径。

ib_apb_m（APB 接口块 - 主向）

  • 功能：处理与 APB 主设备相关的逻辑，含缓冲与位宽转换。
  • 代码实现逻辑：FIFO（a_fifo_rd、d_fifo_rd、w_fifo_rd）缓冲地址/数据/写控制信号。downsize_read_channel 和 downsize_write_mux 通过位宽选择器将大位宽数据拆分为小位宽，写方向使用多路复用器选择正确的字节通道。
  • 子模块：
    • a_fifo_rd：地址 FIFO 读取逻辑。使用同步 FIFO 缓冲地址信号，通过读指针和写指针管理 FIFO 状态，支持背压。
    • d_fifo_rd：数据 FIFO 读取逻辑。缓冲读/写数据，在跨时钟域或突发传输时平滑数据流。
    • w_fifo_rd：写控制 FIFO 读取逻辑。缓冲写使能、字节选通等控制信号。
    • downsize_read_channel：读通道降位宽逻辑。根据 AxSIZE 从大位宽数据中选择正确的字节通道，通过多路复用器输出小位宽数据。
    • downsize_write_mux：写通道降位宽多路复用。将小位宽写数据按字节位置合并到大位宽通道中，使用字节使能掩码控制有效字节。

amib_a664 / ib_a664_m

  • 功能：针对特定配置（a664 协议或特定 IP 核）的 AMIB（AMBA Master Interface Block）与 IB（Interface Block）实例，用于特定主设备的接口适配。
  • 代码实现逻辑：遵循 AMIB/IB 标准接口模式，内部包含地址/数据通道切片和协议转换状态机，针对 A664 协议的特定时序要求进行适配。

二、AXI 子系统

cd_axi_c（AXI 子系统控制器）

  • 定位：AXI 总线互连的顶层控制器。
  • 功能：管理 AXI 协议接口的核心逻辑，包含地址解码、事务跟踪、位宽转换及错误响应处理。
  • 代码实现逻辑：顶层封装各接口块，通过内部总线将 AMIB/ASIB 连接到 switch 网络。包含 GPV 从端接口以支持配置访问。
内部子模块：

amib_S0（AXI 主接口块 - Slave 0 端口）

  • 功能：将内部总线信号转换为 AXI 主设备信号，访问外部 Slave。
  • 代码实现逻辑：ful_regd_slice 在通道中插入完整的寄存器级，切断组合逻辑路径；fwd_regd_slice 和 rev_regd_slice 分别处理前向和反向流水线。通过 VALID/READY 握手协议控制数据流。
  • 子模块：
    • b_master_port_chan_slice（写响应通道切片）：
      • ful_regd_slice：全寄存器切片。在写响应通道中插入完整寄存器，切断组合逻辑路径，优化时序。
      • fwd_regd_slice：前向寄存器切片。仅在正向路径插入寄存器，适用于延迟不敏感的反向路径。
      • rev_regd_slice：反向寄存器切片。仅在反向路径插入寄存器，适用于延迟不敏感的正向路径。
    • r_master_port_chan_slice：读通道切片逻辑。在读数据/地址通道中插入寄存器级，优化时序。
    • w_master_port_chan_slice：写通道切片逻辑。在写数据/地址通道中插入寄存器级。

ib_S0_ib_m（接口块 - Slave 0 到内部 Master）

  • 功能：处理 AXI 主机接口内部逻辑，含位宽转换与协议转换。
  • 代码实现逻辑：maskcntl 根据 WSTRB 信号生成字节选通掩码。downsize_read_channel 从大位宽 FIFO 中按序读出小位宽数据；downsize_write_mux 将小位宽写数据按字节位置合并到大位宽通道中。
  • 子模块：
    • b_boundary_chan_slice：写响应边界通道切片。处理写响应通道的跨时钟域/跨电源域信号传递。
    • r_boundary_chan_slice：读边界通道切片。处理读数据通道的边界信号传递。
    • downsize_read_channel：读通道降位宽逻辑。从大位宽 FIFO 中按序读出小位宽数据，通过计数器控制读取节奏。
    • downsize_write_mux：写通道降位宽多路复用。将小位宽写数据按字节位置合并到大位宽通道中。
    • maskcntl：掩码控制，处理 AXI 的 WSTRB（写选通）信号。
      • wr_iss：写方向 issuing capability（主设备可发出的未完成写事务数上限）。
      • rd_iss：读方向 issuing capability（主设备可发出的未完成读事务数上限）。
      • 代码实现逻辑：使用计数器跟踪当前未完成的读/写事务数，当达到 wr_iss/rd_iss 上限时，通过 maskcntl 逻辑屏蔽新的事务请求，直到有事务完成释放计数器。

ib_S0_ib_s（接口块 - Slave 0 到内部 Slave）

  • 功能：处理 AXI 从机接口内部逻辑，含复杂协议转换与缓冲。
  • 代码实现逻辑：地址格式化模块（axi_read_address_format）根据 AxSIZE 和 AxBURST 计算地址对齐。downsize_axi_write_merge_buffer 缓存拆分的写事务，downsize_axi_write_response_block 聚合多个子事务的 BRESP 响应为单个完整响应返回。
  • 子模块：
    • ar_boundary_chan_slice：读地址边界通道切片。处理读地址通道的跨时钟域信号传递。
    • aw_boundary_chan_slice：写地址边界通道切片。处理写地址通道的跨时钟域信号传递。
    • w_boundary_chan_slice：写数据边界通道切片。处理写数据通道的跨时钟域信号传递。
    • ar_slave_port_chan_slice：读地址从端口通道切片。在读地址通道中插入寄存器级。
    • aw_slave_port_chan_slice：写地址从端口通道切片。在写地址通道中插入寄存器级。
    • w_slave_port_chan_slice：写数据从端口通道切片。在写数据通道中插入寄存器级。
    • b_slave_port_chan_slice：写响应从端口通道切片。在写响应通道中插入寄存器级。
    • r_slave_port_chan_slice：读数据从端口通道切片。在读数据通道中插入寄存器级。
    • axi_read_address_format：读地址格式化。根据 AxSIZE、AxBURST、AxLEN 计算每拍的地址增量，支持 INCR/WRAP/FIXED 突发类型。
    • axi_write_address_format：写地址格式化。与读地址格式化逻辑类似，处理写地址的递增和回绕。
    • downsize_axi_write_control：写控制降位宽逻辑。将大位宽写事务的控制信号拆分为多个小位宽子事务的控制信号。
    • downsize_axi_write_merge_buffer：写合并缓冲。缓存拆分的写事务数据，在收到完整数据后合并为一个大位宽事务发送。
    • downsize_axi_write_response_block：降位宽时的写响应处理。聚合多个子事务的 BRESP 响应为单个完整响应。
    • downsize_read_control：读控制降位宽逻辑。将大位宽读事务的控制信号拆分为多个小位宽子事务。

asib_CPU（AMBA Slave 接口块 - CPU）

  • 功能：针对 CPU 主设备的特定接口块，含地址解码与安全属性检查。
  • 代码实现逻辑：ar_add_decode 和 aw_add_decode 通过比较地址高位与预设范围判断目标 Slave。spi_cdas 检查 AxPROT 信号的安全属性，非安全访问安全区域时触发错误。
  • 子模块：
    • ar_add_decode：读地址解码。将读地址与预设的地址范围比较，输出目标 Slave 的选择信号。
    • aw_add_decode：写地址解码。与读地址解码逻辑类似，生成写方向的目标选择。
    • ar_slave_port_chan_slice：读地址从端口通道切片。在读地址通道中插入寄存器级。
    • aw_slave_port_chan_slice：写地址从端口通道切片。在写地址通道中插入寄存器级。
    • w_slave_port_chan_slice：写数据从端口通道切片。在写数据通道中插入寄存器级。
    • asib_CPU_rd_spi_cdas：读方向 SPI/CDAS 逻辑。检查 AxPROT[1] 的安全属性，非安全访问安全区域时触发错误响应。
    • asib_CPU_wr_spi_cdas：写方向 SPI/CDAS 逻辑。与读方向类似，检查写事务的安全属性。

ib_CPU_ib_m（接口块 - CPU 到内部 Master）

  • 功能：CPU 接口的主向内部逻辑。
  • 代码实现逻辑：apb_async_s 使用握手同步器（两级触发器）实现跨时钟域信号传递。maskcntl 控制 outstanding 事务数。
  • 子模块：
    • apb_async_s：APB 异步桥（从侧）。使用两级触发器同步 pclk 和 aclk 之间的信号，防止亚稳态。
    • b_boundary_chan_slice：写响应边界通道切片。
    • r_boundary_chan_slice：读边界通道切片。
    • maskcntl：掩码控制。限制主设备发出的未完成事务数。

ib_CPU_ib_s（接口块 - CPU 到内部 Slave）

  • 功能：CPU 接口的从向内部逻辑，含升位宽与异步桥。
  • 代码实现逻辑：upsize_axi_write_merge_buffer 将多个小位宽写事务合并为大位宽，通过字节使能掩码控制有效字节。apb_async_m 实现跨时钟域信号同步。
  • 子模块：
    • apb_async_m：APB 异步桥（主侧）。与 apb_async_s 对称，实现 aclk 到 pclk 的信号同步。
    • ar_boundary_chan_slice：读地址边界通道切片。
    • aw_boundary_chan_slice：写地址边界通道切片。
    • w_boundary_chan_slice：写数据边界通道切片。
    • axi_read_address_format：读地址格式化。
    • axi_write_address_format：写地址格式化。
    • upsize_axi_read_channel：读通道升位宽逻辑。将多个小位宽读数据合并为大位宽数据返回。
    • upsize_axi_write_control：写控制升位宽逻辑。将多个小位宽写事务的控制信号合并为大位宽事务的控制信号。
    • upsize_axi_write_merge_buffer：写合并缓冲。缓存多个小位宽写事务的数据，在收到完整数据后合并为一个大位宽事务发送。
    • upsize_axi_write_response_block：升位宽时的写响应处理。将大位宽事务的 BRESP 响应拆分为多个小位宽子事务的响应。
    • ib_ib_slv_apb：内部桥接到 APB 从机的逻辑。

default_slave_ds（默认从设备）

  • 功能：拦截未映射地址的访问，返回 DECERR 错误响应，防止总线挂死。是总线互连的必备保护机制。
  • 代码实现逻辑：当地址解码未命中任何 Slave 时，生成 DECERR 响应。通过状态机在接收到地址后，延迟若干个周期返回错误响应，模拟从设备的响应时序。

ib_gpv_ib_s（GPV 从端接口块）

  • 功能：GPV（全局编程视图）的被动接口，接收配置访问，允许主设备访问 NIC-400 自身寄存器以配置 QoS、安全属性等。
  • 代码实现逻辑：接收配置写请求，解码地址选择目标寄存器，将写入数据锁存到对应寄存器。对于读请求，通过多路复用器选择寄存器值返回。

ib_apb_ib_s（APB 从端接口块）

  • 定位：面向 APB 从设备的接口桥接模块。
  • 功能：结构与 s1_ib_s 类似，但额外集成了 ITB 相关逻辑，用于将 AXI 事务转换为 ITB 格式，实现 AXI 域与 APB/ITB 域的桥接。
  • 代码实现逻辑：核心逻辑与 s1_ib_s 一致（地址解码、通道切片、缓冲）。ITB 相关逻辑将 AXI 事务格式映射为 ITB 格式，地址经过重新编码和位宽调整后通过 ITB 接口发送。
  • 子模块：
    • （与 s1_ib_s 类似的核心逻辑）：包含边界通道切片、从端口通道切片等。
    • axi_to_itb：AXI 到 ITB 协议转换器，将 AXI 事务格式转换为 ITB（互连事务桥）格式，实现跨协议域的事务适配。
    • itb_address_format：ITB 地址格式化，将 AXI 地址格式转换为 ITB 域所需的地址表示方式。

ib_a664_ib_s（A664 从端接口块）

  • 定位：面向 A664 协议（航空电子全双工交换以太网）的接口桥接模块。
  • 功能：结构与 s1_ib_s 类似，额外集成 ITB 逻辑，用于将 AXI 事务转换为 ITB 格式，支持 A664 协议从设备的接入。
  • 代码实现逻辑：与 ib_apb_ib_s 类似，通过 axi_to_itb 将 AXI 事务映射为 ITB 格式，itb_address_format 完成地址转换，然后通过 A664 协议接口发送。
  • 子模块：
    • （与 s1_ib_s 类似的核心逻辑）：包含边界通道切片、从端口通道切片等。
    • axi_to_itb：AXI 到 ITB 协议转换器，将 AXI 事务转换为 ITB 格式。
    • itb_address_format：ITB 地址格式化，转换地址格式以适配 ITB 域。

三、总线矩阵

busmatrix（总线矩阵）

  • 功能：互连核心，负责将多个 Master 请求路由到多个 Slave。
  • 代码实现逻辑：由 switch_ml_build 构建数据通路，switch_ml_map 实现路由仲裁和地址映射，两层协同完成多主多从的互连。
1. switch_ml_build（多层开关构建）
  • 功能：搭建多层开关的数据通路，各层级通常对应不同时钟域或电压域。
  • 代码实现逻辑：rd_spi_tt 和 wr_spi_tt 实现事务跟踪器。每个 TT 内部维护一个计数器（如 tt_cnt），记录当前未完成的事务数。当计数器下溢（underflow）或上溢（overflow）时，通过 OVL 断言触发 FATAL 错误。计数器在事务发出时递增，在收到响应时递减，通过比较器检测是否越界。
  • 子模块：
    • ml_blayer_0 / ml_blayer_1 / ml_blayer_2：多层开关的各层级。
      • rd_spi_tt：读事务跟踪器（Read Transaction Tracker）。
      • wr_spi_tt：写事务跟踪器（Write Transaction Tracker）。
🔑 Transaction Tracker (TT) 核心作用
  1. 事务 ID 跟踪与匹配：记录 ARID/AWID，将 Slave 返回数据路由回正确 Master 通道。
  2. 乱序完成管理：允许不同 ID 事务乱序返回，同一 ID 事务必须按序返回。
  3. 响应聚合与重排序：位宽/协议转换时跟踪拆分子事务，全部完成后生成完整响应。
  4. 背压与流控：监测未完成事务数量，过多时发出背压信号。
  5. 错误处理：生成 SLVERR/DECERR 响应并正确路由回发起 Master。
  • 计数器 tt_cnt：跟踪当前未完成的写事务数。
  • 上溢（Overflow）：计数器超过最大值（如 4bit 从 1111 回绕到 0000），说明事务发起过多而响应未及时返回。
  • 下溢（Underflow）：计数器已为 0 时仍执行减法（如从 0000 变为 1111），说明收到了多余的响应。
  • 断言机制：通过 OVL 库在仿真中实时监测，一旦越界立即触发 FATAL 错误并终止仿真。

📌 TT 位于 switch_ml_build 中，说明事务跟踪是每个 Slave 端口（SPI）独立进行的，实现分布式跟踪。

2. switch_ml_map（多层开关映射）
  • 功能：负责具体路由仲裁与地址映射。
  • 代码实现逻辑：ar_arb_ml0 和 aw_arb_ml0 实现轮询（Round-Robin）或固定优先级仲裁。通过比较各 Master 的请求信号和当前授权状态，使用状态机在单周期内完成仲裁决策。ret_sel_ml0 根据事务 ID 将响应路由回对应的 Master。
  • 子模块：
    • ml_mlayer_0：
      • add_sel_ml0（Address Select）：
        • ar_arb_ml0：读仲裁器，多 Master 竞争同一 Slave 时决定访问权。实现轮询或固定优先级仲裁。
        • aw_arb_ml0：写仲裁器。
        • maskcntl_ml0：掩码控制，限制从设备接受的未完成事务数上限（acceptance capability）。
      • ret_sel_ml0：返回路径选择，决定 Slave 响应返回给哪个 Master。根据事务 ID 路由响应。
      • wr_sel_ml0：写路径选择。
    • ml_mlayer_1 / ml_mlayer_2：其他层级的映射逻辑。

📌 注意区分：ib_m 中的 maskcntl 是主设备接入控制（限制上游发出的请求数），busmatrix 中的 maskcntl 是从设备访问仲裁（限制下游接受的请求数）。两者名称相同但作用层次不同。ib_m 中的 wr_iss/rd_iss 指 issuing capability，busmatrix 中的对应参数指 acceptance capability。

四、寄存器与连接子系统

r_cd_axi_c（寄存器子系统控制器）

  • 定位：与 cd_axi_c 同级的寄存器控制器。
  • 功能：管理 NIC-400 的寄存器访问与控制逻辑，提供软件配置总线互连行为的接口。
  • 代码实现逻辑：通过 GPV 接口接收配置访问，解码地址并分发到对应的寄存器组。id_regs 管理事务 ID 拼接，mnodes_axi_c 和 snodes_axi_c 分别管理主/从节点的配置寄存器。
内部子模块：
模块 功能 代码实现逻辑
ib_gpv_ib_m GPV 主端接口块。主动发起配置访问，读取或修改寄存器。 通过 AXI 读/写事务主动访问 GPV 寄存器空间，内部包含地址生成器和数据回读逻辑。
id_regs ID 寄存器组。管理事务 ID 的扩展与缩减逻辑。ID 由 <IID><SIID><VID> 三部分拼接而成，用于路由事务到正确的源/目标。 将主设备 ID（IID）、从设备 ID（SIID）、虚拟 ID（VID）拼接为全局 ID，用于事务路由。拼接逻辑通过位选和连接操作实现。
mnodes_axi_c 主节点（Master Node）配置。管理所有 AMIB 的寄存器，如 QoS 值、outstanding 事务上限等。 每个主节点对应一组寄存器（max_ot、qos_range 等），通过地址解码选择目标寄存器，写入数据锁存到对应寄存器。
snodes_axi_c 从节点（Slave Node）配置。管理所有 ASIB 的寄存器，如读/写 QoS、安全属性等。 每个从节点对应一组寄存器（read_qos、write_qos、安全属性等），通过地址解码访问，配置值影响仲裁和访问控制逻辑。

rab_conns（RAB 连接模块）

  • 定位：与 r_cd_axi_c 同级。
  • 功能：RAB（Register Access Bridge）连接模块，负责寄存器访问桥的连接逻辑，将 r_cd_axi_c 中的寄存器配置请求路由到总线矩阵的各个节点（Master/Slave 节点），实现配置空间与数据通路的解耦与互联。
  • 代码实现逻辑：通过地址解码确定目标节点，将配置事务转发到对应的 mnodes_axi_c 或 snodes_axi_c。包含多路复用器和解复用器实现配置信号的正确路由。
